Fixes #1857. The excerpt used for the `description`, `og:description` and `twitter:description` meta tags is matched against the raw comment text, so link URLs can leak into it. For the example in the issue, a Markdown comment `Foo.` followed by `[Example Link](https://example.com)` got the excerpt `Foo. example.`, where `example.` is the domain part of the URL.

`Darkfish#excerpt` (also used by Aliki) now cleans up links before matching. Links become their text (`[text](url)` for Markdown comments, `{text}[url]` and `text[url]` for RDoc markup), Markdown images such as badges are dropped, and bare `http(s)`/`ftp` URLs are removed. The issue's example now gives `Foo.`.

On RDoc's own documentation, only three pages get a different description. `CONTRIBUTING.md` and `doc/configuration.md` no longer end in URL or link-syntax fragments (a trailing `github.` and a stray `[`). For `RDoc::TomDoc` the second sentence becomes `The TomDoc specification can be found at .`, which is still not great but no longer mixes in text from an unrelated paragraph. Bare URLs keep their trailing punctuation, so a sentence ending in a URL still ends the sentence. All other pages are unchanged.
