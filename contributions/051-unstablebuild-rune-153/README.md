## 问题理解
`windowconverttab <name> [<icon>]` 没有参数时会直接报错 `command expects at least one argument with tab name`。
但菜单项 "Convert to Tab…"（`cmd/rune/appmenu.go:210`）和各 preset 的 `<ctrl-meta-enter>` 都会预填
`{prompt}windowconverttab<space>`，用户直接按回车就会失败。issue 作者给出了具体方案：name 改成可选，
默认使用 `golang-petname` 生成两个词的名字（与 Rune Agent 的会话 ID 风格相同）；抽一个 `nameGenerator`
接口方便测试；同步更新命令文档和用户文档；指定 icon 时仍须写 name。

## 合理性判断
issue 由维护方提出，并标了 good first issue，方案已经写得很具体。`golang-petname` 已是 go.mod 中的直接依赖，
`cmd/rune-agent/dialogue/dialoguemanager/namegen.go` 里也在用 `petname.Generate(2, "-")`。改动小，合理。

## 改动
- `internal/ide/ex.go`：新增 `nameGenerator` 接口和 `petnameGenerator`，在 `ex.init` 中注入。`convertTab` 遇到缺失或为空的 name 时生成 petname。
- `internal/ide/commands.go`：Synopsis 改为 `[<name> [<icon>]]`，Summary 说明默认名称。
- `cmd/rune/docs/docs/learn/layout-management.md`：同步更新文档。
- `internal/ide/ex_test.go`：新增表驱动测试 `TestConvertTabArgs`（无参数 / 空 name / 只有 name / name+icon），用固定的 generator 校验 tab 的名称和图标。

上次中断时留下的 wip.diff 已逐项核对后并入。删掉了其中一个只跑序列、不做任何断言的集成测试，
也删掉了 "空 name + icon" 用例，因为 issue 明确说指定 icon 时需要显式 name。wip.diff 已删除。
