## Description

Adds the FAQ entry requested in #819 (based on the discussion in #496): when a dependency is pinned to the
same version as the project, a `version_files` entry such as `pyproject.toml:version` also bumps the dependency,
because `update_version_in_files` replaces the version on every line that matches the pattern.

The entry explains that behaviour and the two ways to avoid it:

- use a version provider (`pep621`, `poetry`, `uv`, …) and drop the file from `version_files` (recommended);
- anchor the pattern with `^` (patterns are matched per line), with a note that a `version = "..."` line inside a
  dependency table (e.g. `[tool.poetry.dependencies.foo]`) still matches.

It also adds a small parametrized test in `tests/test_bump_update_version_in_files.py` that pins the documented
behaviour: with `version` the dependency is bumped, with `^version` it is not.

Compared with the earlier attempt (#1910, closed by its author without review), this version describes *why* the
dependency gets bumped (line-by-line matching), mentions the remaining caveat of the `^` anchor instead of saying it
only matches the project version, and backs the claim with a test.
