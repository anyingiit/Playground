## Description

Part 2 of the type-alias inlining, following the same approach as #1863. In public declarations, these aliases are replaced with their expanded types:

| Alias | Inlined as |
|---|---|
| `AnyCol` | `DataColumn<*>` |
| `AnyColumnReference` | `ColumnReference<*>` |
| `AnyColumnGroupAccessor` | `ColumnAccessor<DataRow<*>>` |
| `StringCol` | `DataColumn<String?>` |
| `ColumnGroupReference` | `ColumnReference<DataRow<*>>` |

What I changed and what I left alone:

- Only public signatures change: receivers, parameters, return types, and the constructor parameters of public classes (`ColumnDelegate`, `InsertClause`). In total that is about 200 alias occurrences in 44 files of `core`, plus `toArrowField`/`toArrowSchema` in `dataframe-arrow`, the only other module whose public API used these aliases.
- `AnyColumnGroupAccessor` is expanded all the way to `ColumnAccessor<DataRow<*>>`, not to `ColumnGroupAccessor<*>`. `ColumnGroupAccessor` is an alias too, so stopping there would still leave an alias in completion.
- Left unchanged, as the issue asks: the alias declarations in `aliases.kt`, everything under `impl/`, `internal`/`private` declarations (including the `private` `SortedDataFrameView` in `KotlinNotebookPluginUtils`), function bodies, and KDoc text.
- Imports were updated: unused alias imports were removed and the new type imports were added. ktlint (`runKtlintFormatOverMainSourceSet`) did the formatting, and it also wrapped a few signatures that went past 120 columns.
- No binary or source change, because type aliases are expanded at compile time. `apiCheck` passes without touching `core.api` or `dataframe-arrow.api`.
- `generated-sources` is left for the CI bot to regenerate.
