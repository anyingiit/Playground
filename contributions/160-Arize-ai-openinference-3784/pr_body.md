## Description

`openinference-instrumentation-cohere` wraps the `chat_stream` iterator in a `_Stream` proxy that only ends the LLM span when iteration is exhausted, when it raises, or when the stream's context manager exits. A stream that is dropped by the caller (never iterated, or partially consumed and then abandoned, e.g. `break` out of the loop) or closed via `close()` / `aclose()` never ends its span. `close()` was simply delegated to the wrapped generator by `wrapt.ObjectProxy`, so the call silently disappears from traces.

This PR mirrors what the sibling `openinference-instrumentation-ollama` package already does:

- add `close()` / `aclose()` overrides that close the wrapped stream and then end the span;
- add `__del__` that ends the span (guarded with `try/except BaseException`, so it can never raise during garbage collection);
- widen `_finish` to accept `Optional[trace_api.Status]`. Early-closed / abandoned streams end with status **UNSET**, so they stay distinguishable from completed (OK) and failed (ERROR) streams, and they keep any partial output that was already received.

`_finish` is already idempotent (`with_span.is_finished`), so a stream that completes normally and is later garbage-collected, or is closed twice, still produces exactly one span.

Scope: only the Cohere package. The issue notes that `openinference-instrumentation-together` has a similar gap; I kept this PR small and focused on Cohere.

Tests (no network, monkeypatched raw client + in-memory exporter):
- `test_chat_stream_abandoned_before_iteration_ends_span`
- `test_chat_stream_abandoned_mid_iteration_keeps_partial_output`
- `test_chat_stream_close_ends_span` (also checks a second `close()` / GC does not emit a second span)
- `test_async_chat_stream_aclose_ends_span`

All four fail on `main` (no span is exported) and pass with the fix.

This changes emitted spans only in the sense that previously-missing spans are now exported (status UNSET, same attributes as before), so there is no new trace shape to screenshot.
