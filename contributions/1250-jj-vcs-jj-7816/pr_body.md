## Description

This adds a `sparse()` fileset function that matches the files within the
current working copy's sparse patterns, as proposed in #7816. With it,
`jj log -r 'files(sparse())'` (or `jj log -p -r 'files(sparse()) | empty()'`
from the issue) only shows revisions that touch the sparse checkout, and
expressions like `~sparse()` or `sparse() & glob:"*.rs"` work as usual.

Implementation:

- `FilesetParseContext` gets a `sparse_patterns: Option<&[RepoPathBuf]>` field,
  and builtin fileset functions now receive the whole parse context instead of
  just the path converter. `sparse()` expands to a union of prefix patterns
  (an empty pattern list gives `none()`, the default `.` gives everything).
- `RevsetWorkspaceContext` carries the same field so `files(sparse())` works in
  revsets (including the commit templater's `diff(files)`).
- As suggested by @yuja on the earlier attempt (#9614), the patterns are loaded
  once in `WorkspaceCommandEnvironment::new()`. If they can't be read, or in
  contexts without a working copy (filesets from config such as
  `snapshot.auto-track`), `sparse()` fails with "Sparse patterns are not
  available in this context".

One thing reviewers may want to weigh: for the local working copy,
`sparse_patterns()` loads the tree state, so this adds one tree-state read per
workspace command even when `sparse()` isn't used. If that's not acceptable,
I'm happy to make the loading lazy instead.

Tests: a parser unit test in `lib/src/fileset.rs`
(`test_parse_sparse_function`) and a CLI test in
`cli/tests/test_sparse_command.rs` (`test_sparse_fileset_function`, covering
`jj file list`, `jj log -r 'files(sparse())'`, negation, empty patterns and the
config-context error).
