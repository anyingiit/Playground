## 问题理解

`client.Publish()` 先用 `IsConnected()` 判断；在 `ConnectRetry` 且状态为 `connecting`、或 `AutoReconnect` 且状态为 `disconnecting`（willReconnect=true）时 `IsConnected()` 为 true。之后只有 `reconnecting && qos==0` 会直接 `flowComplete()`。其余情况进入后面的 `switch`：`connecting` / `disconnecting`（以及检查之后状态刚变为 `reconnecting` 的竞态）只打日志“storing publish message”就返回 token。QoS 1/2 会被 `persistOutbound` 存储并在 resume 时完成 token，但 QoS 0 既不持久化也没有 message ID，所以 token 永远不完成，`token.Wait()` 永久阻塞。

## PR title

Complete QoS 0 publish tokens when not connected

## PR body

```markdown
## Related issue

Closes #798

## Description

`Publish()` only completed the token of a QoS 0 message when the status was `reconnecting` at the time of the
initial check. When `IsConnected()` returns true because the client is `connecting` (with `ConnectRetry`) or
`disconnecting` with a reconnect planned (with `AutoReconnect`) - or when the status changes after that initial
check - the later `switch` just logged "storing publish message" and returned the token. QoS 0 messages are
neither persisted nor allocated a message ID, so neither resume nor cleanup could ever complete that token and
`token.Wait()` blocked forever.

This PR adds a first case to the final status `switch`: if the message is QoS 0 and the status is not
`connected`, the message is dropped (QoS 0 is "at most once") and the token completed, matching the existing
behaviour when `reconnecting`. Because this uses the final status read, it also covers the case where the
connection is lost between the initial check and the switch. QoS 1/2 behaviour is unchanged. I also corrected the
comment on the early `reconnecting` case, which said the QoS 0 message was written to the store (it is not).

An alternative would be to complete the token with an error (e.g. `ErrNotConnected`) so callers know the message
was not sent; I went with a successful completion for consistency with the existing `reconnecting` behaviour,
but am happy to change this if you prefer.

**Motivation / disclosure:** I had some spare AI-assistant quota (Claude Code) and am using it to try to
help projects with open good-first-issues. The change was prepared with Claude Code and verified as listed
below. If it doesn't fit, isn't up to your bar, or you'd simply rather not take it — please feel free to
close it, no hard feelings at all 🙂

the first two fail ("QoS 0 publish token did not complete"); with the fix all three pass.
```
