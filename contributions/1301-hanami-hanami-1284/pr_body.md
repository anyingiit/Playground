## Description

Fixes hanami/hanami#1284 (the issue is tracked in hanami/hanami, but the code lives here).

`hanami generate action ... --slice=main` locates the slice block in `config/routes.rb` with
`/slice[[:space:]]*:main/`. That only matches `slice :main, at: "/" do`, so a routes file that
declares slices with parentheses (as generated by e.g. hanamismith) fails:

```ruby
class Routes < Hanami::Routes
  slice(:health, at: "/status") { root to: "show" }
  slice(:main, at: "/") { root to: "home.show" }
end
```

```
cannot find `(?-mix:slice[[:space:]]*:main)` in `config/routes.rb`
```

This PR:

1. Widens the matcher in `Generators::App::Action#add_route_to_block` to
   `/slice[[:space:]]*\(?[[:space:]]*:#{namespace}/`, so `slice(:main, at: "/") do ... end` works.
2. Handles single-line brace blocks such as `slice(:main, at: "/") { root to: "home.show" }`
   (the exact form from the issue). A route can't be injected into a one-line block, and with
   only the matcher change `Dry::Files#inject_line_at_block_bottom` would put the route in the
   wrong place (outside the block). So when the matched slice line is a single-line `{ ... }`
   block, it is rewritten as a multi-line `do ... end` block that keeps the existing body and
   adds the new route:

   ```ruby
   slice(:main, at: "/") do
     root to: "home.show"
     post "/subscribe", to: "home.subscribe"
   end
   ```

   Multi-line `do ... end` blocks still go through `inject_line_at_block_bottom` exactly as before.
   The existing duplicate check (`block_contains?`) runs first, so an existing route in a one-line
   block is still detected and skipped.

Reviewers may want to weigh in on the rewrite in (2): it changes the user's formatting of that one
slice line. The alternative would be to raise a clearer error for single-line blocks; happy to switch
to that if you prefer.
