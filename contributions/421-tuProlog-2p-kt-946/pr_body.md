## Description

`UnifyLogicProgrammingScope.withTheories(...)` defaulted `unificator` to `LogicProgrammingScope.defaultUnificator`. Upgrading a `:dsl-unify` scope that was created with a custom unificator therefore silently switched back to the default strict unificator, and the default `IndexedTheoryFactory` was built on that default too.

This applies the one-line fix proposed in the issue: the parameter now defaults to `this.unificator`. Because `theoryFactory` defaults to `IndexedTheoryFactory(unificator)`, the factory picks up the receiver's unificator as well. The KDoc no longer warns about the pitfall and instead says the receiver's unificator is preserved unless one is passed. The `CoreLogicProgrammingScope.withTheories(...)` overload is unchanged, since a `:dsl-core` scope has no unificator of its own.

As noted in the issue, callers that relied on `withTheories()` resetting to the default unificator will see a behaviour change. They can pass `LogicProgrammingScope.defaultUnificator` explicitly.

A new `TestWithTheories` in `dsl-theory/src/commonTest` checks three things:
- `lp(custom) { withTheories() }.unificator` is the receiver's unificator;
- theories built by the upgraded scope use that unificator;
- an explicitly passed unificator still wins.

The first two fail on `master`; all three pass with the fix.
