## Description

Container grammars (PHP, Vue, Svelte, Astro, MDX, ERB) are skipped by the lazy per-hunk coloring because their nested grammars only activate from the top of the file; the local git/hg/jj backends color them with a full-file pass at load (`enhance_with_full_file_highlight`). The forge PR path parses with `parse_file_patches` but never ran that pass, so these files rendered completely unstyled in `tuicr pr <n>` while `tuicr -r base...head` was fine.

Approach:

- `fetch_pr_data` (background thread) now fetches the old/new contents of container-grammar files, inside the diff branch of the existing `join` so it overlaps with the commit and review-metadata calls, via the existing `ForgeBackend::fetch_file_content` (local blob first when the SHAs are in a checkout, forge API otherwise) and attaches them to two new optional `FilePatch` fields, `old_content` / `new_content`. Only container-grammar files are fetched, capped at 50 per PR so a huge PR without a local checkout doesn't stall on API round trips.
- `parse_file_patches` (main thread) runs `enhance_with_full_file_highlight` for patches that carry contents. Before using a side, it checks that every diff line on that side matches the fetched file at its line number; on mismatch (e.g. a backend whose base cannot be resolved to the merge base) that side is dropped instead of painting lines with another line's spans.
- Non-container files and the local VCS backends are unaffected (the fields stay `None`).
- Added a gotcha entry to `AGENTS.md`.

Not covered here: the commit-range sub-view (`get_pull_request_commit_range_diff`) still parses without contents.
