## 问题理解

`src/types/oid.rs` defines named OID constants. The X9-CM hold-instruction block was:

```
JOINT_ISO_ITU_T_MEMBER_BODY                                   => 2, 2;
JOINT_ISO_ITU_T_MEMBER_BODY_US                                => 2, 2, 840;
JOINT_ISO_ITU_T_MEMBER_BODY_US_X9CM                           => 2, 2, 840, 100400;
JOINT_ISO_ITU_T_MEMBER_BODY_US_X9CM_HOLD_INSTRUCTION{,_NONE,_CALL_ISSUER,_REJECT} => 2, 2, 840, 100400, 2[, 1|2|3];
```

This has two bugs:
1. **Wrong root.** `member-body(2)` is under `iso(1)`, not `joint-iso-itu-t(2)`. RFC 5280 writes
   `holdInstruction ::= { joint-iso-itu-t(2) member-body(2) us(840) x9cm(10040) 2 }`, which is a known erratum.
   The registered OIDs are `1.2.840.10040.2.x` (see https://oidref.com/1.2.840.10040.2, which the issue also cites).
   Real CRLs contain `1.2.840.10040.2.1/2/3`. `2.2` is `association-control` (ACSE). The reporter hit this conflict
   while implementing X.227.
2. **Typo.** The x9-57 arc is written `100400` instead of `10040`.

So the constants never match hold-instruction codes found in real certificates or CRLs.

## PR body

```markdown
## Description

The X9-CM hold-instruction OIDs in `src/types/oid.rs` were defined as
`2.2.840.100400.2.x` (`JOINT_ISO_ITU_T_MEMBER_BODY_US_X9CM_HOLD_INSTRUCTION*`). That value has two problems:

- `member-body(2)` is an arc of `iso(1)`, not `joint-iso-itu-t(2)`. RFC 5280's ASN.1 module writes
  `joint-iso-itu-t(2)` here, but that is a known erratum; the registered OIDs are `1.2.840.10040.2.x`
  (https://oidref.com/1.2.840.10040.2). Also, `2.2` is actually `association-control`.
- The x9-57 arc was written as `100400` instead of `10040`.

So these constants could never match the hold-instruction codes found in real CRLs.

Changes:
- Add `Oid::ISO_MEMBER_BODY_US_X957_HOLD_INSTRUCTION` (`1.2.840.10040.2`) and its `_NONE` / `_CALL_ISSUER` /
  `_REJECT` children. They sit next to the existing `ISO_MEMBER_BODY_US_X957*` constants.
- Keep the old `JOINT_ISO_ITU_T_MEMBER_BODY*` constants (unchanged values) but mark them `#[deprecated]`, with a note
  pointing to the replacement. This keeps the change non-breaking for release-plz/semver-checks. I'm happy to remove
  them or fix their values in place instead if you prefer.
- `oids!` now accepts optional attributes on each entry, which the deprecations need. Existing invocations are unaffected.
- Add a unit test for the new constants.
```
