## 问题理解

Issue (by Maëlle Salmon): add a rule turning `expect_true(all(!which_loop(g2)))` into `expect_all_false(which_loop(g2))`. testthat 3.3.0 added `expect_all_true()` / `expect_all_false()` / `expect_all_equal()`; testthat's own docs describe them as the better-message alternatives to `expect_true(all(x))` / `expect_true(all(!x))`.

## 合理性判断

- Labelled `good first issue` + `new-rule` by the maintainer; fits the existing `testthat` rule group (`expect_match`, `expect_not`, `expect_s4_class`, …) and the contributing guide's "adding a new rule" workflow.
- Semantics checked against testthat source (`R/expect-all.R`): `expect_all_false(x)` = `expect_all_equal_(x, FALSE)`, which **aborts on empty `x`** and compares `x` to `rep(FALSE, n)` with `waldo`, so it is stricter than `all(!x)` (empty input, non-logical `x` such as `c(0, 0)`). Hence the fix is registered as **Unsafe** (only applied with `--unsafe-fixes`), as done for e.g. `all_equal`.

## 改动

- `crates/jarl-core/src/lints/testthat/expect_all_false/expect_all_false.rs` — rule + doc block (Version added 0.7.0, disabled by default, TESTTHAT group). Reports `expect_true(all(!x))` (also `testthat::`/`base::` prefixed, named `object =`), fix → `[ns::]expect_all_false(x)`, strips one level of parentheses (`all(!(x > 1))` → `expect_all_false(x > 1)`). Not reported: `info`/`label` passed to `expect_true()` (no equivalent args), `all()` with >1 or named args (`na.rm`, `all(!x, !y)`), rlang `!!`/`!!!`, `!x | y`. No fix when comments are inside the call (standard `node_contains_comments`).
- `…/expect_all_false/mod.rs` + 2 snapshot files — tests.
- `rule_set.rs` (`TestthatExpectAllFalse`, `fix: Unsafe`), `lints/testthat/mod.rs`, `analyze/call.rs` (inside the testthat block).
- Docs: `docs/rules/expect_all_false.md`, `docs/_quarto.yml`, `docs/rules.qmd` (❗ unsafe fix), `docs/changelog.md`.

## Description

Adds a new rule `expect_all_false` (testthat group, disabled by default) that reports
`expect_true(all(!x))` and suggests `expect_all_false(x)`, which testthat 3.3.0 added
for exactly this case and which gives a much more useful failure message.

- Also works with `testthat::`/`base::` prefixes and `expect_true(object = ...)`.
- Not reported when `info`/`label` is passed to `expect_true()` (no equivalent in
  `expect_all_false()`), when `all()` gets more than one argument (`na.rm`, `all(!x, !y)`),
  or for rlang's `!!`/`!!!`.
- The fix is marked **unsafe**: `expect_all_false()` errors on an empty vector and compares
  against `FALSE` with waldo, so e.g. `x <- c(0, 0)` or `x <- logical()` pass with
  `expect_true(all(!x))` but not with `expect_all_false(x)`.
- `docs/rules/expect_all_false.md` follows the format produced by `just document --no-quarto`.
